# Neo4j database snapshots (dump / restore)

Preserve and restore complete pykci graph states (e.g. a fully ingested +
OSM-enriched city) without re-running the hours-long ingestion. Snapshots are
offline `neo4j-admin database dump` archives of the `neo4j` database, stored in
`backups/` at the repo root (git-ignored).

**Why not `docker commit`?** The graph lives in the named volume
`docker_neo4j_data`, and volumes are *not* part of a container image — a
committed image would contain an empty database. Always dump.

**Version rule:** a dump can only be loaded into the *same or newer* Neo4j
version than the one that wrote it. The compose image is pinned in
`Dockerfile.neo4j` (`neo4j:2025.10.1`); keep the pin ≥ the version noted in the
snapshot inventory below.

All commands run from `docker/` (PowerShell or bash; volume/paths as shown).

## Create a snapshot

```powershell
# 1. Stop the database (dump requires the DB offline)
docker compose stop neo4j

# 2. Dump to backups/ (one-off container on the same image + data volume)
docker run --rm -v docker_neo4j_data:/data -v "D:\PROJEKTE\hcu-cml\pykci\backups:/backups" `
  docker-neo4j neo4j-admin database dump neo4j --to-path=/backups

# 3. Rename with date + content tag (the dump is always written as neo4j.dump)
Rename-Item ..\backups\neo4j.dump neo4j_<content>_<YYYYMMDD>.dump

# 4. Restart
docker compose up -d neo4j
```

## Restore a snapshot

```powershell
docker compose stop neo4j

# Load (--overwrite-destination replaces the current graph!)
Copy-Item ..\backups\neo4j_<content>_<YYYYMMDD>.dump ..\backups\neo4j.dump
docker run --rm -v docker_neo4j_data:/data -v "D:\PROJEKTE\hcu-cml\pykci\backups:/backups" `
  docker-neo4j neo4j-admin database load neo4j --from-path=/backups --overwrite-destination
Remove-Item ..\backups\neo4j.dump

docker compose up -d neo4j
# ready when http://localhost:7474 responds (healthcheck, ~30 s)
```

After restoring, verify against the counts recorded beside the dump
(`backups/*_counts.txt`):

```cypher
MATCH (n) RETURN count(n);                    // nodes
MATCH ()-[r]->() RETURN count(r);             // relationships
MATCH (b:Building) RETURN count(b);
MATCH (o:OsmFeature) RETURN count(o);
MATCH ()-[r:ENRICHED_BY]->() RETURN count(r);
```

The spatial R-tree layers (`features`, `osm_features`, `lod3_features`) are
ordinary graph structure and are contained in the dump — no re-indexing needed
after a restore.
